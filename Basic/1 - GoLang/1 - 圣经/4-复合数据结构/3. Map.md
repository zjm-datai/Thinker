哈希表是一种巧妙并且实用的数据结构，它是一个无序的 key/value 对的集合，**其中所有的 key 都是不同的**，然后通过给定的 key 可以在常数时间复杂度内检索更新或删除对应的 value。

在 Go 语言中，一个 map 就是一个哈希表的引用，map 类型可以写作 `map[K]V` ，其中 K 和 V 分别对应 key 和 value 。map 中所有的 key 都有相同的类型，所有 value 也有着相同的类型，但是 key 和 value 之间可以是不同的数据类型。

其中 K 对应的 key 必须支持 == 比较运算符的数据类型，所以 map 可以通过测试 key 是否相等来判断是否已经存在。虽然浮点数类型也是支持相等运算符比较的，但是将浮点数用做 key 类型则是一个坏的想法，最坏的情况是可能出现的 NaN 和任何浮点数都不相等。对于 V 对应的 value 数据类型则没有任何的限制。

### 最好不用浮点数做 Key

核心原因在于浮点数的精度特性和特殊值行为会导致 key 的比较出现不可预期的结果，从而破坏 map 对 key 唯一性的判断逻辑。

浮点数的二进制存储特性会导致 **数学上相等的数可能存储为不同的近似值**，

使得 `==` 比较返回 false。

```go
package main

import "fmt"

func main() {
    m := make(map[float64]string)
    
    a := 0.1 + 0.2  // 实际计算结果约为 0.30000000000000004
    b := 0.3        // 存储的近似值与 a 不同
    
    m[a] = "result"
    fmt.Println(m[b])  // 输出空字符串（因为 a != b，key 不存在）
}
```

Go 中的 NaN 有一个关键特性，和任何值（包括自身）的 == 比较返回 false 。

这会导致 NaN 作为 key 的时候，无法被 map 正确识别和匹配：

```go
package main

import (
    "fmt"
    "math"
)

func main() {
    m := make(map[float64]string)
    nan := math.NaN()
    
    m[nan] = "special value"
    fmt.Println(m[nan])  // 输出空字符串（无法通过 key 获取值）
}
```

如果非要存，建议转换为字符串或者是整数。
