
《Python 增强提案第 8 号》（也就是大家常说的 PEP 8），是 Python 代码的格式规范指南。当然了，只要语法没毛病，你想怎么写 Python 代码都行。但要是能保持一致的风格，代码读起来就会舒服得多，也更容易理解。和社区里其他 Python 开发者用一套风格，合作项目时能省不少事。就算你的代码只有自己看，按规范来写也能让后续修改更顺手，还能帮你避开很多常见错误。

PEP 8 里详细说明了怎么写出清晰的 Python 代码，而且会随着语言发展不断更新。建议你去官网通读全文（[https://www.python.org/dev/peps/pep-0008/](https://www.python.org/dev/peps/pep-0008/)），这里先挑几条必须遵守的规则说说。

### 空白格式

在 python 中，空格的用法是由语法意义的。程序员们对空格如何影响代码清晰度特别敏感，记住这些规则：

- 缩进用空格，别用制表符（tab）。
- 每级语法缩进用 4 个空格。
- 每行代码长度控制在 79 个字符以内。
- 长表达式需要换行时，续行要比正常缩进多 4 个空格。
- 文件里，函数和类之间要空两行。
- 类里面，方法之间空一行。
- 字典中，键和冒号之间不加空格，同一行的冒号和值之间加一个空格。
- 变量赋值时，等号（=）前后各加且只加一个空格。
- 类型注解里，变量名和冒号之间不加空格，冒号和类型信息之间加一个空格。

### 命名规则

PEP 8 为不同语法元素规定了独特的命名风格，这样读代码时可以一眼分清每个名字的类型：

- 函数，变量和属性用小写字母加下划线 lowercase_underscore 的格式
- 受保护的实例属性用单前导下划线 `_leading_underscore` 。
- 私有实例属性用双前导下划线 `__double_leading_underscore` 。
- 类（包括异常）用首字母大写（CapitalizedWord）的格式。
- 模块级常量用全大写加下划线（ALL_CAPS）的格式。
- 类的实例方法，第一个参数用 self（代表实例本身）。
- 类方法，第一个参数用 cls（代表类本身）。
