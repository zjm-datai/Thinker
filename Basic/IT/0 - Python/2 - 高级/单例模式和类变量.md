在 python 中，单例模式和类变量是两种不同的实现方式，虽然它们都可以在多个实例之间共享状态，但本质是使用场景有很大的区别。

下面我们从概念，实现和应用场景等三个方面进行讲解：

## 类变量

类变量是定义在类中，但在任何方法之外的变量。它由所有实例共享，所有实例访问的都是同一个内存地址。

特点：

- 共享性：所有实例共享同一个类变量
- 全局访问：可通过类名或实例访问
- 易修改：通过类名修改会影响所有实例，但通过修改实例可能实例属性（遮蔽类变量）

```python
class Car:
	wheels = 4

	def __init__(self, color):
		self.color = color

# 创建两个实例
car1 = Car("red")
car2 = Car("blue")

# 所有实例共享类变量
print(car1.wheels)  # 输出: 4
print(car2.wheels)  # 输出: 4

# 通过类名修改类变量
Car.wheels = 6
print(car1.wheels)  # 输出: 6
print(car2.wheels)  # 输出: 6

# 通过实例修改类变量（错误方式）
car1.wheels = 8  # 实际上创建了一个实例属性，遮蔽了类变量
print(car1.wheels)  # 输出: 8（实例属性）
print(car2.wheels)  # 输出: 6（类变量未变）
```

## 单例模式

单例模式是一种设计模式，确保一个类只有一个实例，并提供一个全局访问点，无论创建多少次实例，返回的都是同一个对象。

特点：

- 唯一实例：整个程序中只有一个实例
- 全局访问：通过类方法或属性获取实例
- 状态一致性：所有操作都作用于同一个实例，避免状态冲突

### 实现方法

要实现单例模式，首先要理解它的原理，以下是几个关键点：

1. 实例控制：阻止外部代码直接实例化类，通常通过私有构造函数或元类机制实现
2. 实例缓存：在类的内部维护一个静态变量，存储唯一实例
3. 全局访问：提供一个公开方法或属性来获取缓存的实例

#### 装饰器实现

装饰器实现的核心在于：

- 闭包机制：instance 字典被闭包捕获，在多次调用间保持状态
- 类无关性：同一个装饰器可以应用于多个类，每个类都会有自己的单例实例
- 透明性：对客户端代码完全透明，使用方式与普通类一样

执行流程：

1. 当 `@singleton` 应用到 `Database` 类时，`Database` 类被替换为 `wrapper` 函数
2. 每次调用 `Database()` 实际是调用 `wrapper()` 函数
3. 然后 `wrapper` 函数检查是否已创建实例，如果没有则创建并缓存，否则直接返回缓存实例

```python
def singleton(cls):
	instances = {} # 闭包变量，存储类和实例的映射关系
	def wrapper(*args, **kwargs):
		if cls not in instances:
			instances[cls] = cls(*args, **kwargs) 
			# 首次调用时创建实例
		# 总是返回缓存的实例
		return instances[cls]

	return wrapper

@singleton
class Database:
	def __init__(self):
		print("初始化数据库连接")

# 创建多个实例，实际是同一个对象
db1 = Database() # 输出：初始化数据库连接
db2 = Database() # 不输出，直接返回 db1
print(db1 is db2)
```

python 允许在内部函数中修改外部函数的可变对象，所以无需额外使用 `nonlocal` 关键字。

#### 元类实现

```python
class SingletonMeta(type):
	_instances = {}
	def __call__(cls, *args, **kwargs):
		if cls not in cls._instances:
			cls._instances[cls] = super().__call__(*args, **kwargs)
		return cls._instances[cls]

class Config(metaclass=SingletonMeta):
    def __init__(self):
        print("加载配置文件")

# 创建多个实例，实际是同一个对象
cfg1 = Config()  # 输出: 加载配置文件
cfg2 = Config()  # 不输出，直接返回 cfg1
print(cfg1 is cfg2)  # 输出: True
```



## 区别

| **对比项**   | **类变量**               | **单例模式**                 |
| --------- | --------------------- | ------------------------ |
| **实例数量**  | 可创建多个实例，共享类变量         | 全局唯一实例                   |
| **状态管理**  | 类变量被所有实例共享，但可通过实例意外修改 | 所有操作作用于同一实例，状态严格一致       |
| **应用场景**  | 简单数据共享（如配置、计数器）       | 需要严格控制实例数量的场景（如数据库连接、日志） |
| **实现复杂度** | 简单，直接定义变量即可           | 需借助装饰器、元类或基类实现           |

### 如何选择

- **使用类变量**：
    - 仅需共享数据，不需要限制实例数量。
    - 数据可能被不同实例独立修改（需注意数据一致性）。

- **使用单例模式**：
    
    - 需要确保全局唯一实例（如线程池、配置管理器）。
    - 避免多个实例导致的资源冲突（如数据库连接）。

### **总结**

类变量是 Python 的基础特性，用于实例间共享数据；而单例模式是一种设计模式，用于控制实例数量。选择哪种方式取决于你的需求：如果只需数据共享，用类变量；如果需要严格控制实例唯一性，用单例模式。
