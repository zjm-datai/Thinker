
在之前的数字人项目中，我们是通过两个接口进行数字人播报的。

第一个接口是获得数字人回复，流式的回复输出，然后等流式结束之后，把完整的文本发送给 /tts 接口，得到语音文件给到浏览器，然后播放。

这样，巨他妈的慢 ~

如果要让浏览器流式输出，好像是对二进制字节流的格式是有要求的。我们现在是可以进行流式的字节流输出的，我们的接口，但是前端还是没有实现对流式字节流的播放。

硅基流动的接口好像不支持流式输出 webm 的字节流，当然后端是可以处理。

但我们还是没有解决如何流式进，流式出这种神级的要求。

现在只是可以，流式文本输出，输出结束之后，统一给语音模型，然后得到流式输出的音频流，流式播放还不行（我相信可以）。
