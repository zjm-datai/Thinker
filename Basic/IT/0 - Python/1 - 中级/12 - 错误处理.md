没有使用异常捕获机制，当错误发生时，Python 解释器无法处理，就会输出完整的 traceback 信息

taceback 一般就是会打印完整的函数调用栈

在 Python 的 traceback 信息中，**最下方的一行就是错误实际发生的位置**，而上方的内容则是完整的函数调用栈（Call Stack）。

我的理解是在项目中写异常捕获的作用就是减少大量 traceback 的出现，这也是程序员本身对代码充分了解的体现,知道哪里会出错，然后用少量的日志打印给出了关键信息。

主动捕获异常的前提是预判可能的风险点（如网络请求失败、文件不存在、数据格式错误等），这正是对业务和代码充分理解的体现。合理的异常处理能让代码更健壮，也降低了后期维护成本。

简单说，异常捕获就像给程序加了一层 "安全网"—— 既避免了意外崩溃的尴尬，又能通过可控的日志快速定位问题，是编写高质量代码的重要实践。
