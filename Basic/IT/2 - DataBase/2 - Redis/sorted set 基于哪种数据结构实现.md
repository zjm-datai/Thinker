
Redis 的 sorted set 有序集合底层实现会根据数据规模动态选择两种数据结构进行组合：

### 小规模数据：压缩列表 ziplist

当有序集合满足以下条件时，会使用压缩列表存储：

- 当元素数量少于 zset-max-ziplist-entries 配置（默认 128）
- 每个元素的成员（member）和分值（score）的字符串长度都小于 zset-max-ziplist-value 配置（默认 64 字节）

压缩列表是一种紧凑的连续内存结构，将所有元素按照顺序存储在一块连续的内存中，通过指针跳转访问下一个元素，他的优势在于内存占用少，但不适合大规模数据或频繁修改的场景。

### 大规模数据：跳表（skiplist）+ 哈希表（dict）

当数据规模超过上述阈值时，Redis 会自动将结构转换为 **跳表 + 哈希表** 的组合：

#### 跳表（skiplist）

跳表是 sorted set 的核心排序结构，它的设计思路是：

- 在普通链表基础上增加多层 "索引"，实现快速查找
- 每个节点包含：成员（member）、分值（score）、多个向前指针（指向不同层级的下一个节点）
- 支持平均 O (logN) 复杂度的插入、删除和范围查询

跳表的核心价值是高效支持 **按分值排序的范围操作**（如获取排名前 N 的元素）。

#### 哈希表（dict）

哈希表作为辅助结构，存储 "成员 -> 分值" 的映射关系，实现：

- O (1) 复杂度的分值查询（通过成员快速获取其分值）
- O (1) 复杂度的成员存在性判断

两种结构共享同一份成员和分值的内存（通过指针关联），确保数据一致性。
