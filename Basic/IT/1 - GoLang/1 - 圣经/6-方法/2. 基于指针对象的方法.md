
在 go 中，方法接收器分为值接收器和指针接收器：

- 值接收器：调用方法会对接收器进行拷贝（类似函数参数的默认拷贝行为），因此在方法内部修改接收器的值，不会影响原对象。
- 指针接收器：调用方法时候传递的是对象的指针（地址），不会拷贝原对象，因此：
	- 可以在方法内部直接修改原对象的值（实现更新变量的需求）
	- 当对象体积较大的时候，避免拷贝带来的性能损耗（符合避免大参数拷贝的需求）

```go
func (p *Point) ScaleBy(factor float64) {
	p.X *= factor // 直接修改原对象的 X, Y 字段
	p.Y *= factor
}
```

### 指针接收器的语法细节

方法名的完整表示是 `(*Point).ScaleBy` 括号 `()` 是必须的。

原因：如果写成 `*Point.ScaleBy` ，Go 会优先解析为 `*(Point.ScaleBy)`（即先取 `Point` 的 `ScaleBy` 方法，再对其解引用），这在语法上是错误的，因此需要用括号明确优先级。

调用时的简化：虽然方法声明为 `(*Point).ScaleBy` ，但调用时无需显式取地址，Go 会自动转换。例如：

```go
var p Point 
p.ScaleBy(2) // 等价于 (&p).ScaleBy(2)，Go 自动处理指针转换
```

### 类型和指针接收器的约定

现实开发中：如果一个类型有一个方法使用了指针接收器，那么该类型的所有方法都应该使用指针接收器，即使某些方法不需要修改对象。

目的是为了保持接口的一致性，避免使用者混淆哪些方法会修改源对象，哪些不会。

## Nil 也是也该合法的接收器类型

在 Go 语言的世界里，有个看似奇怪却十分实用的特性：nil 居然可以作为方法的接收器！这就好比给一个 “空盒子” 也装上了操作按钮，只要提前约定好 “空盒子” 该如何响应，就能玩出不少花样。​

先来看个直观的例子。假设我们要实现一个整数链表，用 `*IntList` 类型表示。当这个指针是 nil 时，我们约定它代表一个空链表。这时候给它定义一个Sum方法，专门计算链表中所有元素的和：

```go
type IntList struct {
	Value int
	Tail *IntList
}

func (list *IntList) Sum() int {
	if list == nil {
		return 0
	}
	return list.Value + list.Tail.Sum()
}
```

这段代码的巧妙之处在于，当链表为空的时候，sum 方法会返回 0，完美符合 “空链表的和为 0” 的逻辑。就像计算器遇到空输入时，默认输出 0 一样自然。不过要注意，在定义这种允许 nil 作为接收器的类型时，一定要在注释里说清楚 nil 代表什么，就像例子中做的那样，不然其他开发者用起来可要犯迷糊了。
