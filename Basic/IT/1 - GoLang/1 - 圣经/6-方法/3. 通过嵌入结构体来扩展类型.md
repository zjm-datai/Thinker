
先说结论：

GoLang 的嵌入结构体（struct embedding）是一种简化写法，可以让我们把一个结构体“放进”另一个结构体中，相当于自动“继承”了它的字段和方法，但其实**不是继承**，而是一种**组合关系**（has-a）。

```go
type Point struct {
    X, Y float64
}

type ColoredPoint struct {
    Point          // 嵌入 Point
    Color color.RGBA
}
```

你看，我们没有写 `X float64` 和 `Y float64`，而是把整个 `Point` 嵌进来了。

**这样 ColoredPoint 就“自动”拥有了 X 和 Y 字段。**

```go
var cp ColoredPoint
cp.X = 1       // 直接用，不用写 cp.Point.X
cp.Y = 2
fmt.Println(cp.X, cp.Y)
```

因为 `Point` 被嵌入了，它的字段就像是 `ColoredPoint` 自己的字段一样，**可以直接用，不用点出来**。

当然方法也可以使用。

虽然看起来像面向对象语言里的“子类继承父类”，但其实不是。你可以把它理解成：

> ColoredPoint 有一个 Point（has-a），不是 is-a。

### 嵌入指针的好处？

我们还可以嵌入结构体的指针：

```go
type ColoredPoint struct {
	*Point
	Color color.RGBA
}
```

这时候两个 ColoredPoint 可以**共享一个 Point 对象**，也就是它们的位置是共享的。

```go
p := ColoredPoint{&Point{1, 1}, red}
q := ColoredPoint{&Point{5, 4}, blue}

q.Point = p.Point  // 现在 p 和 q 共享一个 Point

p.ScaleBy(2)
fmt.Println(p.Point, q.Point) // 都变成了 {2, 2}
```

### 一个线程安全的缓存

也就是多个 goroutine 来查缓存的时候，不能互相打架，要用锁 Mutex 控制。

以前的写法是这样的：

```go
var mu sync.Mutex // 定义一个锁
var mapping = make(map[string]string) // 定义一个 map 当缓存

func Lookup(key string) string {
	mu.Lock() // 加锁
	v := mapping[key] // 访问缓存
	mu.Unlock() // 解锁
	return v
}
```

这样没问题，但缺点是：

- `mu` 和 `mapping` 是两个变量，放在全局不太优雅
    
- 没有很好地“打包”成一个缓存对象

#### 把锁和缓存放在一个结构体里

我们可以这样做：

```go
var cache = struct {
	sync.Mutex // 嵌入一个锁
	mapping map[string]string
} {
	mapping: make(map[string]string)
}
```

这行代码干了两件事：

1. 定义了一个匿名结构体（没有名字的 `struct`）
    
2. 把 `sync.Mutex` 和 `mapping` 都放在一起，起名叫 `cache`

等价于：

```go
type MyCache struct {
    sync.Mutex
    mapping map[string]string
}

var cache = MyCache{mapping: make(map[string]string)}
```

然后我们可以这样用：

```go
cache.Lock()
v := cache.mapping["someKey"]
cache.Unlock()
```

就像 `cache` 本身拥有 `Lock()` 和 `Unlock()` 一样。

通过把 `sync.Mutex` 嵌入结构体，我们可以让这个结构体**自动拥有锁的功能**，然后把锁和数据组合成一个整体变量，既方便管理又简化语法。
