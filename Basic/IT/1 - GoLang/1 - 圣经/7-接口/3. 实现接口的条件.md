
一个类型如果拥有一个接口需要的所有方法，那么这个类型就实现了这个接口。

例如 `*os.File` 类型实现了 io.Reader，Writer，Closer，和 ReadWriter 接口。`*bytes.Buffer` 实现了 Reader，Writer，和 ReadWriter 这些接口，但是它没有实现 Closer 接口因为它不具有 Close 方法。

Go 的程序员经常会简要的把一个具体的类型描述成一个特定的接口类型。举个例子，`*bytes.Buffer` 是 io.Writer；`*os.Files` 是 io.ReadWriter。

接口指定的规则非常简单：表达一个类型属于某个接口只要这个类型实现这个接口。所以：

```go
var w io.Writer
w = os.Stdout
w = new(bytes.Buffer)
w = time.Second // compile error: time.Duration lacks Write method

var rwc io.ReadWriteCloser
rwc = os.Stdout
rwc = new(bytes.Buffer) // complie error: *bytes.Buffer lacks Close method
```

这个规则甚至适用于等式右边本身也是一个接口类型

```go
w = rwc
rwc = w // compile error: io.Writer lacks Close method
```

因为 ReadWriter 和 ReadWriteCloser 包含 Writer 的方法，所以实现了 ReadWriter 和 ReadWriterCloser 的类型必定也实现了 Writer 接口。

在进一步学习前，必须先解释一个类型持有一个方法的表示当中的细节。

假设我们定义了一个具体的类型，名字叫 T。给 T 绑定方法时，有两种情况： 

- 有的方法，接收者是 T 本身（也就是用值类型当接收者）； 

- 有的方法，接收者是 `*T`（也就是用 T 的指针类型当接收者）。 

这里有个需要注意的点：如果有一个 T 类型的变量，我们直接用它调用那些接收者是 `*T` 的方法，是允许的。这是因为编译器会帮我们自动做一件事——偷偷取这个变量的地址，把它转成 `*T` 类型再去调用方法。

但这只是编译器给我们的一个方便（也就是“语法糖”），并没有改变一个本质：**T 类型的值本身，并不真正拥有那些接收者是 `*T` 的方法**。 这一点会直接影响到接口的实现。因为一个类型要实现某个接口，必须真正拥有这个接口要求的所有方法。既然 T 类型的值没有那些 `*T` 才有的方法，那它能满足的接口要求，自然就可能比 `*T` 类型少。

```go
package main

import "fmt"

// 定义一个具体类型 Person
type Person struct {
	Name string
}

func (p Person) GetName() string {
	return p.Name
}

func (p *Person) SetName(newName string) {
	p.Name = newName
}

type Human interface {
	GetName() string
	SetName(newName string)
}

func main() {
	// 创建一个 Person 类型的变量
	person := Person{Name: 'Alice'}
	// 创建一个 *Person 类型的变量
	personPtr := &Person{Name: "Bob"}

	// 调用方法的区别
	fmt.Println(person.GetName()) // 正常：Person 有 GetName 方法
	person.SetName("Alice") // 语法糖：实际上会转为 (&person).SetName()
	fmt.Println(person.GetName()) // 输出 Alice 修改成功

	var human Human

	human = person // 报错：Person 没有 SetName 这个方法
	human.SetName("Bobby")
	fmt.Println(human.GetName()) // 输出 Bobby
}
```

### 接口就像一个封装器，只暴露规定的方法

比如说 os.Stdout 本身有 Write，Close 等很多方法，但是如果把它赋值给 io.Writer 接口变量，就只能调用 io.Writer 里面声明的 Write 方法，Close 方法虽然存在，但是接口藏起来了，用不了。

接口里面的方法越多，要求就越严格：

比如 io.ReadWriter 比 io.Reader 多个 Write 方法，所以可以实现 io.ReadWriter 的类型更少（必须同时有 Read 和 Write）。

```go
package main

import (
	"fmt"
	"io"
	"os"
)

// 自定义文件处理结构体
type MyFile struct {
	file *os.File
}

// 实现Read方法
func (f *MyFile) Read(p []byte) (n int, err error) {
	fmt.Println("调用MyFile的Read方法")
	return f.file.Read(p)
}

// 实现Write方法
func (f *MyFile) Write(p []byte) (n int, err error) {
	fmt.Println("调用MyFile的Write方法")
	return f.file.Write(p)
}

// 实现Close方法
func (f *MyFile) Close() error {
	fmt.Println("调用MyFile的Close方法")
	return f.file.Close()
}

// 实现自定义的额外方法
func (f *MyFile) CustomMethod() {
	fmt.Println("调用MyFile的自定义方法")
}

func main() {
	// 创建一个文件
	file, _ := os.Create("test.txt")
	myFile := &MyFile{file: file}

	// 赋值给不同的接口变量
	var r io.Reader = myFile      // 只包含Read方法的接口
	var rw io.ReadWriter = myFile // 包含Read和Write方法的接口
	var c io.Closer = myFile      // 只包含Close方法的接口

	// 只能调用接口中声明的方法
	r.Read(nil)       // 合法
	// r.Write(nil)    // 不合法，io.Reader接口没有Write方法
	// r.Close()       // 不合法，io.Reader接口没有Close方法

	rw.Read(nil)      // 合法
	rw.Write(nil)     // 合法
	// rw.Close()      // 不合法，io.ReadWriter接口没有Close方法

	c.Close()         // 合法
	// c.Read(nil)     // 不合法，io.Closer接口没有Read方法

	// 原始类型可以调用所有方法
	myFile.Read(nil)
	myFile.Write(nil)
	myFile.Close()
	myFile.CustomMethod()
}
```

### 空接口 interface{} 是个特例

它里面没有任何方法，所以所有的类型都可以实现它 -- 不管是基础类型 bool int string ，复合类型，还是自定义类型（结构体，指针），都可以赋值给类型为 interface{} 的变量。

这虽然看着好像没有什么用，但是其实超级有用的：

- 比如 fmt.Println 之所以可以接收任何类型的参数，就是因为它内部使用了空接口
- 但是空接口里的值不能直接操作（因为没方法），后面会学 “类型断言” 来提取它的值。

### 接口可以灵活分组类型的共性，不用改变原类型

比如有一堆具体的类型：Album 专辑、Movie 电影 ............

可以使用 Aritifact 接口把他们的共性（标题，创作者，创建时间）抽出来，不管它们原来是什么类型；

后来发现 Audio 和 Video 都有播放流，时长，格式这些共性，直接新定义一个 Streamer 接口就可以了，不用改 Audio 和 Video 的代码。 

比如说：

```go
type Audio struct {
	title string
	duration int
	format string
}

func (a *Audio) GetDuration() int {
	return a.duration
}

// 获取格式
func (a *Audio) GetFormat() string {
    return a.format
}

// 已有的Video类型
type Video struct {
    name string
    length int    // 时长(秒)
    codec string  // 编码格式如h264
}

// Video的播放方法
func (v *Video) Play() {
    fmt.Printf("播放视频: %s, 编码: %s, 时长: %d秒\n", v.name, v.codec, v.length)
}

// 获取时长
func (v *Video) GetDuration() int {
    return v.length
}

// 获取格式
func (v *Video) GetFormat() string {
    return v.codec
}
```

现在我们新定义 Streamer 接口：

```go
// 新定义的接口
type Streamer interface {
    Play()
    GetDuration() int
    GetFormat() string
}
```

此时，Audio 和 Video 类型**不需要做任何修改**，就已经实现了 Streamer 接口，因为它们已经实现了接口要求的所有方法。

我们可以直接这样使用：

```go
func main() {
    audio := &Audio{title: "我的歌", duration: 200, format: "mp3"}
    video := &Video{name: "我的视频", length: 300, codec: "h264"}
    
    // 可以直接赋值给Streamer接口变量
    var s1 Streamer = audio
    var s2 Streamer = video
    
    s1.Play()  // 播放音频: 我的歌, 格式: mp3, 时长: 200秒
    s2.Play()  // 播放视频: 我的视频, 编码: h264, 时长: 300秒
}
```
