类型断言其实就是 Go 语言中的一种检查接口中到底是什么的操作。使用方法就是 `x.(T)` ，其中 x 必须是一个接口类型的变量，T 是我们需要断言的类型。

一共有两个情况：

#### 第一种情况：T 是具体类型

这个时候类型断言的作用在于：检查盒子中的东西是不是 T 类型，如果是就把他取出来使用，不是就报错 panic 。

假设我们有个 `io.Writer` 类型的接口变量 `w`（可以理解为一个「能写东西的盒子」），里面装的是 `os.Stdout`（这是个 `*os.File` 类型的具体值，既能读又能写）。

```go
var w io.Writer  // 盒子 w
w = os.Stdout    // 盒子里装了 *os.File 类型的 os.Stdout

// 断言：看看盒子里是不是 *os.File 类型
f := w.(*os.File)  // 成功！f 就是盒子里的 os.Stdout（类型是 *os.File）

// 再断言：看看盒子里是不是 *bytes.Buffer 类型
c := w.(*bytes.Buffer)  // 失败！因为里面是 *os.File，所以会 panic（报错）
```

#### 第二种情况：T 是接口类型

这时类型断言的作用是：**检查盒子里的东西是否满足 T 接口的要求（即是否有 T 接口需要的所有方法）。如果满足，就得到一个新的接口变量（类型是 T），可以用 T 接口的方法；如果不满足，就会报错**。

```go
var w io.Writer
w = os.Stdout  // 里面是 *os.File（有读和写方法）

// 断言：看看盒子里的东西能不能满足 io.ReadWriter 接口（需要读和写方法）
rw := w.(io.ReadWriter)  // 成功！rw 现在是 io.ReadWriter 类型，能调用读和写方法

// 换个例子：如果盒子里装的是只有写方法的 *ByteCounter
w = new(ByteCounter)  // *ByteCounter 只有写方法，没有读方法
rw = w.(io.ReadWriter)  // 失败！因为不满足读方法要求，会 panic
```

#### 不想报错？用「双返回值」模式

上面两种情况如果断言失败都会报错（panic），但实际开发中我们可能只想「试探」一下，不想让程序崩溃。这时可以用双返回值的写法：  

```go
value, ok := x.(T)
```

- 如果断言成功：`ok` 是 `true`，`value` 是盒子里的值（类型是 T）。
- 如果断言失败：`ok` 是 `false`，`value` 是 T 类型的零值（不会报错）。

```go
var w io.Writer = os.Stdout

// 试探：盒子里是不是 *os.File？
f, ok := w.(*os.File)  
// 成功：ok 是 true，f 就是 os.Stdout

// 再试探：盒子里是不是 *bytes.Buffer？
b, ok := w.(*bytes.Buffer)  
// 失败：ok 是 false，b 是 nil（*bytes.Buffer 的零值）
```

```go
// 如果盒子里是 *os.File，就用 f 做些操作
if f, ok := w.(*os.File); ok {
    // 这里可以放心使用 f（比如调用 *os.File 的特有方法）
}
```
