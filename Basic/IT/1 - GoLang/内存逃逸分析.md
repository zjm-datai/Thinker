
## 什么是内存逃逸？

在 Go 中，变量通常会被分配到两个地方：

栈（Stack）：函数内部的局部变量，生命周期短，函数返回后会被自动释放
堆（Heap）：需要长期存在的变量，会触发垃圾回收 GC

当一个变量的生命周期超出了其声明的函数范围，或者编译器无法确定其生命周期的时候，这个变量就会从栈逃逸到堆上，这就是内存逃逸。

## 内存逃逸的原理

### 栈内存的特性：严格的函数生命周期绑定

栈内存的管理是编译器主导的，确定性的：

- 栈内存的分配和释放完全由函数调用链控制（遵守先进后出原则）
- 函数调用的时候，其内部局部变量会被压入栈中，函数返回的时候，这些变量会被自动弹出并释放
- 这种机制的前提是：编译器在编译的时候明确知道变量的生命周期（和函数的生命周期一致）

### 为什么会逃逸

当变量的生命周期超出函数范围，或编译器无法确定其生命周期时，栈内存的管理机制就会失效：

#### 变量生命周期超出函数范围

如果函数返回了局部变量的指针（或引用），这个变量就不能再分配到栈上。

```go
func getPtr() *int {
    x := 10
    return &x  // x 的地址被返回，生命周期超出函数
}
```

- 如果 x 分配在栈上，函数返回后栈帧会被销毁，x 的内存会被释放

- 此时外部拿到的指针会指向一块 "无效内存"，导致程序崩溃

- 因此编译器必须将 x 分配到堆上，确保其在函数返回后仍能被安全访问

#### 编译器无法确定变量的生命周期

有时变量的生命周期不是 "非黑即白" 的，编译器无法在编译时做出确定性判断：

- 例如切片的长度是动态计算的 `make([]int, n)` n 会在运行时候才确定
- 又如变量被存入全局容器 `globalMap["key"] = &x` 编译器无法预知它会被使用多久

这时编译器会采取 "安全策略"：将变量分配到堆上，由垃圾回收器（GC）在运行时根据实际引用情况回收。

Go 中栈和堆的区别？逃逸到堆上有什么影响？

栈上分配效率高，由编译器自动管理，函数返回后释放；堆上分配需要 GC 介入，可能影响性能。频繁的内存逃逸会增加 GC 压力，降低程序性能。
