
#### embedding 向量检索的原理是什么，如果保证检索的准确性

通过向量库的算法计算 embedding 向量和向量库中向量的相似度进行检索。

提高检索的准确性的方式可以从很多维度进行分析：

1. 知识库的合理切分，对于不同的文档要有不同的切分策略，像我们的通用做法是将所有文档转换为 md 格式，利用这种天然具有合理结构化的文本进行规则的切分会方便很多。这个过程可能需要 ocr 甚至利用大模型清洗语料。

2. 查询重写也很重要，对于原始的一句话拿去做嵌入和检索，实际上效果不会太好，比如我们之前的场景中在做辅助诊疗的时候，我们会首先提取出原始 query 中的药品信息等东西去分别检索，这样对症下药。

3. 人工辅助大模型打标，对文本片段进行元数据的标注，在检索之后通过元数据进行再筛选，可以做到更细粒度的检索。

4. 重排序模型的引入，在检索之后再重排序，可以针对语义进行更好的检索排序，因为重排模型实际上对语义的识别更清晰嘛

#### function calling 如何解析用户的意图？

这一块我感觉是一个触发的问题，什么时候大模型可以识别到这个触发并结构化输出过去。当对话历史，上下文过长的时候，是一个比较考验我们提示词设计的事情。

在过去我们做心理咨询场景的时候，遇到过一种场景就是需要及时识别到患者线下就医，推送线下咨询页面的需求。当时我是这么处理的：最简单一开始的版本我们是使用了非常蠢的逻辑，每次对话，我们都会用一个大模型去判断是否有这个意愿，因为我们发现在小模型的场景下，拆分成不同的节点，会优化效果，如果把所有的工具判断都放到一个大模型里面，对于一个 7b 的模型来说会吃不消。
