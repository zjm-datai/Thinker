
计算机不能直接识别和执行用高级语言写的指令，必须使用编译程序（也叫编译器）把 C 源程序翻译成二进制形式的目标程序，然后再将该目标程序和系统的函数库以及其他目标程序连接起来，形成可以执行的目标程序。

一，首先，编写 C 后缀源代码

二，然后，对源程序进行编译，先用 C 编译系统提供的预处理器（又叫预处理程序或预编译器）对程序中的预处理指令进行编译预处理。例如，对于 `#include<stdio.h>` 指令来说，就是把 stdio.h 的头文件内容读进来，取代 `#include<stdio.h>` 行。由预处理得到的信息与程序其他部分一起组成一个完整的，可以用来进行正式编译的源程序，然后由编译系统对该源程序进行编译。

编译的作用在于对源程序进行检查，判定它有没有语法方面的错误，如果有就发出错误信息，告诉编程人员认真检查改正。修改程序之后重新进行编译，如果还有错，再发出错误信息这样。如此反复进行，直到没有语法错误为止。这个时候，编译程序自动把源程序转换为二进制形式的目标程序（在 Visual C++ 中后缀为 .obj，如 f.obj）。如果不特别指定，这个程序一般存放在用户当前目录下面，此时源文件没有消失。

三，进行连接处理。经过编译所得到的二进制目标文件（后缀为 .obj）还不能供给计算机直接执行。前面已经说明，一个程序可能包含若干个源程序文件，而编译是以源程序文件为对象的，一次编译只可以得到一个源程序文件相对应的目标文件（也叫目标模块），它只是整个程序的一部分，必须把所有编译后得到的目标模块连接装配起来，再和函数库相连接成一个整体，生成一个可供计算机执行的目标程序，称之为可执行程序，在 Visual C++ 中其后缀为 .exe 。

当一个程序由多个C语言源文件（.c 文件）组成时，编译器一次只能处理一个源文件，并为每个源文件生成一个对应的目标文件（.o 或 .obj）。 

举个例子会更清楚： 假设我们有一个程序由3个源文件组成： 

- main.c（主程序） 
- calc.c（计算相关函数） 
- print.c（输出相关函数） 

编译时的处理过程是： 

1. 编译 main.c → 生成 main.o（第一个目标文件） 
2. 编译 calc.c → 生成 calc.o（第二个目标文件） 
3. 编译 print.c → 生成 print.o（第三个目标文件） 

这三个目标文件都是独立的，彼此之间还没有建立联系。编译器不会一次性处理所有的.c文件，而是"逐个处理"，每个源文件对应生成一个目标文件。 

只有在后续的 “链接” 阶段，链接器才会把这 3 个目标文件以及需要的库文件组合在一起，最终生成一个可执行程序。 

这种方式的好处是：当你修改了其中一个源文件（比如 calc.c），只需要重新编译这个文件即可，不需要重新编译所有文件，提高了开发效率。

当然即使一个程序只包含一个源程序文件，编译后得到的目标程序也不能直接运行，也要经过连接阶段，因为要和函数库进行连接，才能生成可执行程序。以上的连接工作是由一个连接编辑程序 linkage editor 的软件来实现的。

四，运行可执行程序，得到运行结果。
