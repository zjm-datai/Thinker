
The browser's native `<audio>` tag can only play complete URLs or Blobs and does not support incremental data feeding. To address this, HTML5 provides MediaSource Extensions (MSE).

## Initializing MediaSource

### Create a MediaSource and Bind It to `<audio>`

```js
const audio = document.getElementById("audio");
const mediaSource = new MediaSource();
audio.src = URL.createObjectURL(mediaSource);
audio.pause();
```

Here, we create a MediaSource object—the core of MSE (MediaSource Extensions). It acts as a container for audio/video data, dynamically receiving media chunks and providing them to the media element for playback.​

**audio.src = URL.createObjectURL(mediaSource)​**

This line creates a temporary URL for the MediaSource object. Assigning this URL to the audio element's src property establishes a connection between the audio element and the MediaSource.​

This way, the audio element no longer plays a complete URL directly but receives data through the MediaSource.​

**audio.pause();**

Initially pause audio playback. Playback will start by calling audio.play() after the first streaming chunk is returned from the interface.

### Wait for the sourceopen Event of mediaSource

```js
mediaSource.addEventListener("sourceopen", () => {

	const sourceBuffer = mediaSource.addSourceBuffer('audio/mpeg');
	sourceBuffer.mode = 'sequence';
	// Data will be pushed later using sourceBuffer.appendBuffer(dataChunk)

});
```

**addSourceBuffer('audio/mpeg')​**

Tells the browser, "I will push MPEG audio data here next."​

**mode = 'sequence'​**

Plays data in the order it is pushed, without out-of-order merging.​

The sourceopen event is triggered when a MediaSource object is associated with an `<audio>` or `<video>` tag, and the browser switches its state from closed to open, ready to receive data.

```js
const mediaSource = new MediaSource();
audio.src = URL.createObjectURL(mediaSource);
```

After executing this code, the browser initializes this virtual media source.

**Internal Preparation​**

The browser does two things:​

- Parses the objectURL just set and "hooks" it to your MediaSource object.​

- Completes necessary internal state transitions from MediaSource.readyState === "closed" to "open".​

**Trigger sourceopen​**

Once the above preparation is complete (usually in the next event loop or during the media element's first loading cycle), the browser dispatches a sourceopen event to your mediaSource object. At this point, you can safely call:

```js
const sb = mediaSource.addSourceBuffer('audio/mpeg');
```

**Triggers Only Once​**

sourceopen triggers only once when transitioning from "closed" to "open". If you later call mediaSource.endOfStream() to enter the "ended" state, it will not trigger again.

## Chunked Reading and Enqueuing: Processing Fetch Stream Data

### Get response.body.getReader()

```js
const reader = response.body.getReader();
```

This allows asynchronous reading via reader.read(), which returns { done, value } each time:

- value: A binary chunk (of type Uint8Array).
- done: true when the stream ends.

### Continuously Read in a Loop (the pump Function)

```js
async function pump() {
  const { done, value } = await reader.read();
  if (done) { /* Mark reading as complete */ return; }
  queue.push(value);
  // Immediately try to send one chunk from the queue to sourceBuffer
  if (!sourceBuffer.updating && queue.length > 0) {
    sourceBuffer.appendBuffer(queue.shift());
    // … Start playback after the first append and calculate TTFB…
  }
  pump();  // Recursively continue reading the next chunk
}
pump();
```

The queue is A buffer to temporarily store read chunks that haven’t been appended yet, preventing concurrent operations on sourceBuffer.

**After each appendBuffer, the browser triggers an updateend event**, indicating the chunk has been processed and the next chunk can be appended.

## The updateend Event: Maintaining Stream Continuity

```js
sourceBuffer.addEventListener("updateend", () => {
  if (queue.length > 0 && !sourceBuffer.updating) {
    sourceBuffer.appendBuffer(queue.shift());
  } else if (readingDone && queue.length === 0) {
    mediaSource.endOfStream();
  }
});
```

When a chunk finishes appending, updateend is emitted.

- If there’s remaining data in the queue, continue with appendBuffer.
- If the server has sent all data (readingDone === true) and the queue is empty, call endOfStream() to notify the browser, "The audio stream has ended."
